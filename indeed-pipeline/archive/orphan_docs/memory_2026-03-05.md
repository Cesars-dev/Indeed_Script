## Key Architecture Facts

- `_PROFILES` dict is loaded **once at module import** from Supabase. CF detection now updates it in-memory so same-session re-tries are correctly blocked.
- Stone-walled reset is **lazy** (checked on each `apply_to_job()` call), not scheduled.
- `_gemini_loop()` is now a thin wrapper — no timeout, no retry logic. Natural exit conditions: `done`, `failed`, `skip`, 10 consecutive failures, or 50 steps exhausted.
- Profile data (name/phone/salary) comes from DB — no more `.env` overrides for per-profile fields.

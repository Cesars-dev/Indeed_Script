# Milestone 7 — AdsPower Profile Attach (Architecture Rewrite)

## Status: COMPLETE ✅

---

## Problem Solved

M1–M6 used cookie injection + headless nodriver Chrome on VPS. This was blocked:
- nodriver headless Chrome on VPS = always blocked by Indeed's Cloudflare/TLS fingerprint at network level
- Cookie injection is unnecessary if AdsPower profiles stay logged in permanently

The fix: AdsPower profiles ARE persistent browser sessions. Stop launching nodriver's own Chrome. Instead, start an AdsPower profile (already logged in, proxied, fingerprinted) and attach nodriver to it as a behavior layer only.

---

## Architecture Change

| Layer | Old (M1–M6) | New (M7+) |
|-------|-------------|-----------|
| Browser | nodriver headless Chrome | AdsPower profile (existing browser) |
| Fingerprint | nodriver spoofing (detected) | AdsPower (full TLS/JA3/canvas/WebGL spoof) |
| Session | cookie files exported from Mac | AdsPower profile (logged in permanently) |
| Proxy | `proxy_manager.py` code | Baked into AdsPower profile at creation |
| Human behavior | nodriver | nodriver (role preserved) |

**Flow:**
```
GET /api/v1/browser/start?user_id={id}&api_key={key}  → returns debug_port
uc.Browser.create(host="127.0.0.1", port=debug_port)  → attaches to AdsPower's browser
page.goto(apply_url)   → already logged in, correct fingerprint, correct proxy
human-like: scroll → delay → click → per-char typing
GET /api/v1/browser/stop?user_id={id}&api_key={key}
```

## What Was Done

### Code Rewrites
- `src/nodriver_indeed.py` — full rewrite: attaches to AdsPower via `debug_port`, human-like behavior (random delays, scroll-before-click, per-char typing), no cookie or proxy logic
- `src/apply_runner.py` — full rewrite: `PROFILE_IDS` list (10 profiles), round-robin rotation by job index, no cookies/proxy

### Files Archived (moved to `archive/`)
- `scripts/export_cookies.py` — no longer needed
- `scripts/rerun_failed_cookies.py` — no longer needed
- `config/cookies/` — no longer needed
- `src/proxy_manager.py` — no longer needed

### VPS Cleanup
- Killed stale processes: `proxy_relay.py` ×4, `socks5_relay.py`, `http.server`
- Deleted junk scripts: `stress_test_v2/v3`, `stress_residential`, `debug_search`, `debug_search2`, `get_jobs`, `mock1.md`, `verify_noproxy`, `test_jobpage`, `test_proxy_chrome`
- Kept: `stress_test.py` (original, for reference)

### Infrastructure
- MCP servers rebound to `127.0.0.1` on VPS (were public on `0.0.0.0`)
- Antigravity `mcp_config.json` updated: `localhost:3001/mcp` (was VPS IP)
- autossh tunnel via launchd (`~/Library/LaunchAgents/com.vps.tunnel.plist`): always-on, survives Mac sleep/reboot
  - Forward: `localhost:3001-3003` → VPS MCP servers
  - Reverse: `VPS:50325` → Mac AdsPower API

### API Discoveries (corrected)
- AdsPower `browser/start` = **GET** not POST
- nodriver attach = `Browser.create(host="127.0.0.1", port=debug_port)` — NOT `connection_url` (that kwarg is silently ignored, causing nodriver to launch its own Chrome)

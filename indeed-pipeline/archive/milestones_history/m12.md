## Session Persistence Rules (learned the hard way)

1. **`JSESSIONID` is the real session** — not `indeed_sess` (obsolete) or `CTK` (tracking-only)
2. **AdsPower is ground truth** for email ↔ user_id mapping — never trust Supabase alone
3. **Fresh profiles need manual first login** — CF sees zero history = instant Turnstile
4. **Let session age 24h** before any script touches a newly logged-in profile
5. **`export_cookies.py` works on fresh profiles** — WITH google.com warmup first. Slot 3 confirmed automated login on fresh profile with JSESSIONID saved. Warmup is critical.
6. **Never restart profiles repeatedly** — each stop/start cycle risks cookie loss
7. **Burned proxies stay burned** — CF ties IP history to risk score; rotate to fresh proxies on reset
8. **setup_profiles.py deletes ALL indeed group profiles** — if interrupted mid-run, Supabase goes stale.
   Always verify AP profile count matches Supabase after running.

## Root Causes Summary (from prior session)

### 1. Email ↔ Profile mismatch (critical — now fixed)
8/10 profiles had wrong emails in Supabase. All previous logins used wrong Google accounts.
AdsPower `username` field = ground truth.

### 2. Automated login on fresh profiles triggers CF
`export_cookies.py` navigates directly to indeed.com on zero-history profiles = instant Turnstile.
Manual first login is the ONLY safe method for fresh profiles.

### 3. Proxies were flagged
Old 10 proxies burned from repeated suspicious sessions. Rotated to fresh proxies on reset.

### 4. `SESSION_COOKIES` check was wrong
`CTK` is always present (tracking token). Script falsely validated sessions that were actually
CF challenge pages. Now checks `JSESSIONID` which only appears after successful login.

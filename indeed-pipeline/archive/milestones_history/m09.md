Running `test_local.py` against a live AdsPower profile revealed:

## Required Behaviour (M9 goal)

Mimic how a human uses Indeed:
1. Open browser → land on `indeed.com` homepage (~5–10s idle)
2. Use the search bar or browse jobs naturally (~10–20s)
3. Click into a job listing
4. Read the job page (~10–20s, scroll)
5. Click "Apply now" / "Easy Apply"
6. Fill form and submit

Total time on site before applying: **30–60 seconds minimum**

## Key Technical Findings

### nodriver tab management
- `browser.tabs` returns all open tabs in the AdsPower browser
- `browser.get(url)` opens a **new tab** every time — do NOT use it for navigation
- Correct pattern: grab `tabs[0]`, close extras, then use `await tab.get(url)` for navigation on that same tab

```python
tabs = browser.tabs
for tab in tabs[1:]:
    await tab.close()
page = tabs[0]
await page.get("https://www.indeed.com")   # navigates in-place, no new tab
```

### Human delay targets
| Action | Delay |
|--------|-------|
| After profile opens | 3–5s |
| Landing on homepage | 8–15s |
| Between pages | 5–10s |
| Reading job page | 10–20s |
| Before clicking Apply | 3–6s |
| Between form steps | 2–4s |

### CAPTCHA handling
- Triggered when navigating directly to a search URL on first load
- Fix: always land on `indeed.com` homepage first, wait, then navigate to search
- If CAPTCHA still appears: pause and wait for user to solve manually (test script), or rotate to next profile (production)

### AdsPower API corrections (discovered M8)
- `browser/start` = **GET** not POST
- Attach = `Browser.create(host="127.0.0.1", port=debug_port)` — NOT `connection_url`
- Both `nodriver_indeed.py` and `test_local.py` corrected

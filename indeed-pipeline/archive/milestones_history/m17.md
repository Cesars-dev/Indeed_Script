### 2. Rewrote `_complete_application` as a state machine

**Design principle:** Loop runs on current page state, not a fixed sequence. Each check is independent — if a step doesn't appear, its handler is a no-op.

```python
async def _complete_application(page, docx_path, profile=None, debug_dir=None):
    for step in range(15):
        # Screenshot current state
        # Check: success text → return success
        # Check: disqualification text → return disqualified
        # Check: "Upload a resume" in content → click it (once)
        # Check: input[type='file'] present → upload file (once)
        # Check: "questions" in URL or "Answer these questions" in content:
        #   → JS: click "Yes" for all unanswered radio groups
        #   → JS: fill empty year/experience inputs with years_exp
        # Check: "Submit your application" button → click, return success
        # Fallback: click "Continue" or "Next"
        # If none found → return failed (stuck)
```

**Variability handled automatically:**
- Jobs with no employer questions → radio/text JS is a no-op
- Jobs with 2 pages of questions → loop runs handlers twice
- Jobs that skip resume choice → `resume_selected` guard harmless
- Jobs where profile already has resume → upload choice never appears, skipped

**New status: `"disqualified"`** — application was submitted but employer screening failed. Distinct from `"skipped"` (never applied) and `"failed"` (script error).

### 3. Dynamic per-step screenshots

Added `_screenshot(page, debug_dir, label)` helper and wired it into the loop.

**Every run creates:**
```
/tmp/apply_debug/{user_id}_{unix_timestamp}/
  step_00_smartapply.indeed.com_beta_indeedapply.png
  step_01_smartapply.indeed.com_beta_indeedapply.png
  step_02_smartapply.indeed.com_beta_indeedapply_form_questions-module.png
  ...
```

Screenshot is taken BEFORE any action on that step, so you see exactly what the script saw. URL slug in filename makes it readable without opening the image.

**Workflow for new step types:** Run script → open `/tmp/apply_debug/` → look at last screenshot before `"Stuck on step N"` → add handler for that page → repeat.

## Current Architecture

```
apply_to_job(url, docx, user_id)
  ├── _start_profile()           → AdsPower API start
  ├── Browser.create(host, port) → attach via CDP
  ├── _get_tab()                 → tab[0] untouched, work in tab[1]
  ├── page.get(indeed.com)       → warmup
  ├── _clear_cloudflare()        → Layer 2 (Turnstile) + Layer 1 (JS wait)
  ├── _delay(15-25s)             → cf_clearance bake
  ├── _human_scroll()            → human reading behavior
  ├── page.get(apply_url)        → navigate to job
  ├── _clear_cloudflare()        → CF check again
  ├── _detect_apply_type()       → already_applied / external / easy_apply
  ├── find apply button          → "Apply with Indeed" / "Easy Apply"
  ├── _complete_application()    → state machine: 15-step loop
  │     ├── screenshot per step → /tmp/apply_debug/{user_id}_{ts}/
  │     ├── resume choice       → click "Upload a resume"
  │     ├── file upload         → send_file(docx_path)
  │     ├── employer questions  → JS: Yes radios + fill experience inputs
  │     ├── submit              → "Submit your application"
  │     └── Continue/Next       → advance between steps
  └── finally:
        page.get(indeed.com)    → leave warm tab
        _stop_profile()         → AdsPower API stop
```
